# Устранение проблем с логированием

## Проблема: В сохраненном файле только один лог

Если в сохраненном файле логов только один лог (например, `[RootLayout] Global error handlers initialized`), это означает, что:

1. **Логи не перехватываются до краша** - краш происходит до того, как логи успевают записаться
2. **Логи не выводятся в release сборке** - возможно, они удаляются на этапе сборки
3. **Краш происходит на нативном уровне** - до того, как JavaScript успевает обработать ошибку

## Решения

### 1. Проверьте, что логи действительно записываются

Добавьте тестовое логирование в начале приложения:

```typescript
// В app/_layout.tsx, в useEffect
console.log('[Test] This is a test log');
console.log('[Test] Logger service has', loggerService.getLogCount(), 'logs');
```

### 2. Используйте logcat для просмотра логов в реальном времени

```bash
npm run logs:android
```

Это покажет все логи, которые выводятся в консоль, даже если они не сохраняются в файл.

### 3. Включите автоматическое сохранение при ошибках

В `app/_layout.tsx` уже включено автоматическое сохранение:

```typescript
loggerService.setAutoSaveOnError(true);
```

### 4. Сохраняйте логи вручную перед воспроизведением краша

1. Откройте экран логов (`/logs`)
2. Нажмите кнопку "Сохранить"
3. Воспроизведите краш
4. Снова откройте экран логов и сохраните еще раз

### 5. Проверьте настройки Babel

Убедитесь, что в `babel.config.js` не удаляются `console.log` в production:

```javascript
// babel.config.js должен НЕ содержать transform-remove-console
```

### 6. Добавьте логирование в критических местах

Убедитесь, что логирование добавлено в:
- `handleSubmit` в `camera.tsx`
- `submitPhoto` в `photoService.ts`
- `uploadPhoto` в `supabase.ts`
- `uriToArrayBuffer` в `supabase.ts`

### 7. Используйте logcat для отладки

Если логи не сохраняются в файл, используйте logcat для просмотра логов в реальном времени:

```bash
# Просмотр всех логов
adb logcat

# Просмотр только логов React Native
adb logcat ReactNativeJS:V *:S

# Просмотр только ошибок
adb logcat *:E
```

### 8. Проверьте права доступа

Убедитесь, что приложение имеет права на запись файлов:
- `WRITE_EXTERNAL_STORAGE` (уже добавлено в `app.json`)

### 9. Диагностика

Добавьте диагностическое логирование:

```typescript
// В начале handleSubmit
console.log('[Camera] handleSubmit called');
console.log('[Camera] Logger has', loggerService.getLogCount(), 'logs in memory');
console.log('[Camera] Auto-save enabled:', loggerService.isAutoSaveOnErrorEnabled());
```

### 10. Альтернативный способ: логирование через нативный код

Если JavaScript логи не работают, можно добавить логирование через нативный Android код, но это требует изменений в нативном коде.

## Рекомендации

1. **Всегда используйте logcat** для отладки release сборок
2. **Сохраняйте логи вручную** перед воспроизведением краша
3. **Проверяйте логи в реальном времени** через logcat во время воспроизведения краша
4. **Добавляйте больше логирования** в критических местах

## Пример использования

```bash
# Терминал 1: Запустите logcat
npm run logs:android

# Терминал 2: Воспроизведите краш в приложении
# Логи будут видны в реальном времени в терминале 1
```
